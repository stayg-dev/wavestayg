# WAVE STAY-G · 양양

제공된 Figma `7GQ2ihw8K70UklPTEQfD1X`, 페이지 `0:1`을 구현한 Next.js 16 / React 19 / TypeScript 프로젝트입니다.

2026-09-22: 실제 PMS 판매일보 연동을 구현했습니다. 관리자 승인·수분양자 로그인·일반 예약 신청의 최신 기준과 배포 전 설정은 [PMS 예약 설정 가이드](docs/pms-booking-setup.md)를 따릅니다. 아래 날짜별 설계 기록은 과거 상태이며 최신 구현보다 우선하지 않습니다. 배포와 운영 DB 반영은 수행하지 않았습니다.

## 실행

```bash
npm install
npm run dev
```

로컬 주소: http://localhost:3000

```bash
npm test
npm run lint
npm run build
```

공지 관리자와 서버 API를 위해 Next.js 서버 실행 방식으로 구성됩니다. 개발은 `npm run dev`, 프로덕션은 `npm run build` 후 `npm start`로 실행합니다. Vercel에서는 Next.js 기본 빌드 설정을 사용하며 Output Directory를 `out`으로 지정하지 않습니다.

## 화면

- `/`: 해변 사진 전환, 날짜/인원 검색, 객실·부대시설·위치·갤러리
- `/rooms/`: 객실 유형 필터, 상세 보기, 예약 화면 이동
- `/facilities/`: 부대시설 안내
- `/location/`: 위치, 연락처, 교통, 주변 명소
- `/notice/`: PMS DB 공지 조회, 분류 필터, 펼쳐 보기, 페이지 이동
- `/admin/`: 관리자 로그인, 공지 작성·조회·수정·삭제 (저장 즉시 공개)
- `/contact/`: 원본 연락처를 활용한 문의 안내
- `/reservation/`: 예약·조회 선택
- `/reservation/book/`: 객실 현황·요금 확인 후 일반 예약 신청
- `/reservation/lookup/`: 신청 번호·비밀번호로 서버 예약 조회
- `/owners/`: 수분양자 로그인·예약 신청·이용 내역·비밀번호 변경
- `/admin/reservations/`: 수분양자 계정 발급, 수분양자/일반 예약 확인·승인·반려·취소

## 원본 재현과 구현 범위

Figma의 사진, 로고, 아이콘을 다운로드해 `public/assets/`에서 제공합니다. Pretendard 가변 글꼴도 로컬에 포함하며 라이선스는 같은 디렉터리에 있습니다. 원본의 회색 이미지 영역은 사진이 배치되지 않은 디자인이므로 회색으로 유지했습니다. 데스크톱 레이아웃을 기준으로 모바일에서 한 열로 재배치합니다.

2026-09-11 변경된 Figma를 반영했습니다. 객실은 별도 컴포넌트 기준 11개 타입이며 홈·목록·상세·예약에서 같은 객실 데이터를 사용합니다. 요금은 사용자 선택에 따라 별도 컴포넌트의 58,000원으로 통일했습니다. 예약 계산은 1박 요금 × 숙박 수에 세금 10%를 더합니다. 부대시설은 루프탑·프런트 데스크·주차장으로 갱신했습니다. [반영 기준과 원본 내 불일치](docs/figma-sync-2026-09-11.md)를 기록했습니다. 다른 숙소 이름의 샘플 공지는 제거했으며 공지사항은 관리자에서 직접 등록합니다.

현재 예약 경로는 PMS 객실 조회·서버 신청·관리자 승인 방식입니다. 요금표 금액을 적용하며 세금 10% 추가와 쿠폰 15% 할인은 제거했습니다. 실제 온라인 결제·이메일 발송·금전 환불은 제공하지 않습니다. 메인 예약 버튼은 공개 보류 요청에 따라 준비중 안내를 유지합니다.

이전 예약 미리보기 코드는 참고용으로 남아 있으나 실제 예약 경로에서 사용하지 않습니다. 신규 신청은 PMS DB에 저장하며 카드 번호나 CVC를 수집하지 않습니다. 운영 전 환경변수·스키마 패치·객실 타입 매핑·실제 명부 설정이 필요합니다.

2026-09-10 최소 설계는 **타입·호실 선택 없는 수분양자 신청 → 홈페이지 관리자 전용 대기 목록에서 확인·승인 → PMS 예약 등록 성공 → 확정**입니다. 기존 /admin을 확장하고 Next.js·PMS API·PMS DB를 재사용합니다. 승인 전에는 신청만 저장하고 실제 PMS 예약·재고에는 반영하지 않습니다. 승인 시 PMS 등록과 혜택 차감을 함께 처리하며 실패·결과 불명확 건은 관리자 확인 목록에 남깁니다. 사용자 관리의 기본 항목은 호실·이름·전화번호·잔여 박수이며, 내부 기준 연도와 올해·이월 잔여를 구분하여 API 호출 시 연간 부여·이월·소멸을 DB에 반영합니다. 스케줄러는 사용하지 않습니다. 결제는 현장, 재고·배정은 기존 PMS, 취소·예외 조정은 홈페이지 관리자 확인으로 처리합니다. 별도 재고 엔진·혜택 원장·자동 결제·발송 시스템은 만들지 않습니다. 이는 아직 구현되지 않은 설계이며 위의 기존 데모 화면과 구분됩니다. [PMS 연동 설계](docs/pms-integration-design.md)와 [수분양자 예약 설계](docs/owner-booking-design.md)를 기준으로 구현합니다.

2026-09-11에는 [일반 예약 설계](docs/general-booking-design.md)를 추가했습니다. 일반 예약도 홈페이지의 `/admin/reservations`에서 확인·승인하고 PMS 등록 성공 후에만 확정합니다. 수분양자 전용 목록은 유지하고 신청·승인·취소 서비스를 공유합니다. 현장 정산, 비회원 조회, 조건 변경 시 고객 합의, 연동 실패 처리까지 문서로 정리했으며 기능은 아직 구현하지 않았습니다.

`npm test`는 예약 계산 및 공지·인증 로직을 검사합니다. 빌드 후 `npm run test:http`로 공지 API 통합 테스트를 실행할 수 있습니다. 이 테스트는 실제 PMS DB를 수정하지 않습니다.

공지사항 설정은 [공지 관리자 설정 가이드](docs/notice-admin-setup.md)를 따릅니다. PMS 주소는 상수로 유지하고, Vercel에는 `PMS_PROJECT_ID`, `PMS_API_KEY`, `ADMIN_PASSWORD_HASH`, `ADMIN_SESSION_SECRET`을 설정합니다. `npm run admin:setup`으로 관리자 설정을 준비할 수 있습니다. 실제 비밀값은 Git 제외 환경파일에 보관하며 공개 저장소에 올리지 않습니다. 등록·수정·삭제는 관리자만 가능하며 저장하면 바로 공개됩니다. 임시저장·게시 전환·상단 고정은 없습니다. 수분양자 전용 영역은 예약관리만 제공합니다.

배포는 사용자가 직접 진행합니다. 로컬 Sites 연결 설정은 제거했습니다. 이 설정 제거 자체가 기존 원격 사이트를 삭제하지는 않습니다.
